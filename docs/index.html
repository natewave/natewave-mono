02
        
Tell them apart
Checked at 11 px on a 1× screen
      

      
Line ends carry most of the information people use to identify a letter, and look-alikes are
        confused with each other, not at random. So each confusable group gets distinct stroke ends and silhouettes.
        Every group below was rendered at 11 px on a 1× pixel grid in light and dark themes, next to Iosevka, JetBrains
        Mono, Intel One Mono and Atkinson Hyperlegible Mono.

      

        

          
0OoØ

          
An oval zero with a long centre dot. The dot rules out Ø; the narrower oval rules out O.

          
requirement Unicode UTS #39 on confusables

        

        

          
1lI|

          
Identity sits at the stroke ends: 1 has a flag and a foot, l a tail, I full bars, | is a plain rule.

          
moderate Fiset et al., 2008

        

        

          
ij!¦

          
The i and j dots are 10% larger than Iosevka's default, and i's tail sets it apart from l.

          
moderate Bernard et al., 2016

        

        

          
9gq

          
A double-storey g breaks the g, q, y look-alike group of descending letters.

          
moderate Bernard et al., 2016

        

        

          
8B3

          
A flat-topped 3 stays clear of 8 and B. JetBrains Mono makes the same choice.

          
convention JetBrains Mono

        

        

          
5S$

          
The dollar's bar runs straight through, so $ never reads as S or 5.

          
requirement coding requirement

        

        

          
2Z7

          
A curved neck on 2; straight diagonals on Z and 7.

          
requirement coding requirement

        

        

          
6bG

          
6 has a straight diagonal stroke, b a vertical ascender, G a spur and an inward hook.

          
requirement coding requirement

        

        

          
,.;:

          
Periods and commas are 15% larger than Iosevka's default, so punctuation survives small sizes.

          
convention Input, Source Code Pro

        

        

          
'"`´

          
Straight quotes; the grave and acute accents slant in opposite directions.

          
requirement coding requirement

        

        

          
([{

          
Rounder parentheses, square brackets and curly braces: three different silhouettes.

          
requirement coding requirement

        

        

          
rn m

          
On a monospace grid rn and cl take two cells while m and d take one, and r gets a foot to fill its cell.
          

          
moderate Beier & Larson, 2010

03
        
Proportions
Units per 1,000 em
      

      
At 11–14 px, code sits at or below the size where reading speed starts to drop, and x-height is
        what sets effective size. So the x-height is raised to 0.545 em while ascenders and descenders keep 0.43 of it,
        and the cell widens from Iosevka's 0.5 em to 0.6 em.

04
        
Ligatures: off until you ask
What you type is what you
          see
      

      
A ligature that draws != as ≠ can't be told apart from the real ≠ character, and no study shows
        programming ligatures help. Natewave Mono ships with them switched off. If you like them, the discretionary
        dlig feature turns them on.
      

      

        
dlig
          

          

        

        
-> => <= >= != == === !== <- |> <| :: ... <!-- -->
          <> ++ ||

      

      
Butterick (2019) argues ligatures can misrepresent code;
        readers' preferences still differ (Wallace et al., 2022), so the choice is yours.

09
        
The evidence
30 sources, each read at least as an
          abstract
      

      
Almost all legibility research tested prose, proportional fonts or print. No study tests fonts
        for reading code, so every row below is extrapolated to code, and each is labelled with how strong its evidence
        is.

      
strong replicated, or reviews agreemoderate one controlled study, or caveatsconvention type-design practicepreference what people like

      

        

          
            

              Decision
              Value
              Basis
              Evidence
            

          
          
            

              x-height
              545 (Iosevka 520)
              Code at 11–14 px sits at or below the critical print size, and x-height sets effective size (Legge & Bigelow, 2011).
              strong
            

            

              Extenders
              Ascender 780, cap 730, descender −235
              A large x-height costs letters with ascenders and descenders (Larson & Carter, 2016).
              moderate
            

            

              Width
              0.6 em cell (Iosevka 0.5)
              Wider letters help recognition and low-vision acuity (Beier et al., 2021; Oderkerk & Beier, 2022); width changes
                eye movements, not speed (Minakata & Beier,
                  2021).
              moderate
            

            

              Spacing
              Sidebearings × 0.9, same pitch
              Standard monospaced spacing is already optimal (Chung, 2002; Pelli et al., 2007); fixed-width fonts improved with
                slightly less letter spacing (Slattery et al., 2016).
              
              moderate
            

            

              Line height
              1.35 em
              1.2–1.4 em beats tight setting (Paterson & Tinker,
                  1932; Kruk & Muter, 1984; Ling & van Schaik, 2007; Chung, 2004).
              moderate
            

            

              Weight
              Stems ≈ 0.090 em; Bold 700
              Boldness helps at small sizes (Beier &
                  Oderkerk, 2019); low contrast suits sans designs (Minakata & Beier, 2022).
              moderate
            

            

              Polarity
              One Regular, no thinner dark cut
              Dark-on-light is more legible, most of all at small sizes (Piepenbrock et al., 2013, 2014; Dobres et al., 2016); grade only mattered in
                light mode (Palmén et al., 2023). In dark themes,
                add 1 px of size instead.
              strong moderate
            

            

              Glyph identity
              Tailed l, flagged 1, dotted oval 0, double-storey g
              Line ends identify letters (Fiset et al.,
                  2008); breaking look-alike groups cut errors in a monospace (Bernard et al., 2016); narrow letters improve
                when widened (Beier & Larson, 2010).
              moderate
            

            

              Serifs
              Sans; serifs and tails only on narrow letters
              Serifs alone don't change legibility (Arditi
                  & Cho, 2005).
              moderate
            

            

              Operators
              One axis; low _; larger period
              No study found. Visible underscores matter for under_score names (Sharif & Maletic, 2010).
              convention
            

            

              Italic
              9.4°, mostly oblique
              Italics read slightly slower (Tinker & Paterson,
                  1928; Rello & Baeza-Yates, 2013); no
                study compares cursive with oblique.
              moderate convention
            

            

              Ligatures
              Off by default; dlig opt-in
              No study of programming ligatures; they can misrepresent code (Butterick,
                  2019); readers differ (Wallace et al., 2022).
              convention preference
            

            

              Hinting
              Hinted and unhinted builds
              No study isolates hinting; ClearType doesn't beat well-tuned greyscale (Sheedy et al., 2008).
              convention

Install
Unhinted for macOS and high-DPI; hinted for Windows and
          1× Linux
      

      
The download on this page is the unhinted TTF build of the current build plan. Hinted TTFs suit
        Windows and 1× Linux screens: build them with the ttf::NatewaveMono target (see Build from source),
        or get them from GitHub
          Releases once a version is published.

      

        
        
        
        
      

      

        
Unzip the download, then double-click each .ttf and choose Install, or copy them into your fonts
          folder:

        

          
cp NatewaveMono/*.ttf ~/Library/Fonts/

        

        
If the family doesn't show up in Font Book or your apps, remove the four
          files from ~/Library/Fonts and install them again, then restart the app.

      

      

        
Copy the fonts into your user font folder and refresh the font cache:

        

          
mkdir -p ~/.local/share/fonts/NatewaveMono
cp NatewaveMono/*.ttf ~/.local/share/fonts/NatewaveMono/
fc-cache -f
fc-list :spacing=mono family | grep "Natewave Mono"

        

      

      

        
Unzip the download, select the four .ttf files in File Explorer, right-click and choose Install (or
          Install for all users). On a standard-density screen a hinted TTF renders crisper; see the note above.
        

      

      

        
Build it yourself from the repository root with Node.js and Git (add ttfautohint for hinted
          targets):

        

          
git clone --depth 1 --branch v34.4.0 https://github.com/be5invis/Iosevka.git
cp private-build-plans.toml Iosevka/
cd Iosevka && npm install
npm run build -- --jCmd=4 webfont-unhinted::NatewaveMono
